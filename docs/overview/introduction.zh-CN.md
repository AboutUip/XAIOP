## 1. 目的

XAIOP（eXtensible AI Output Protocol）是一套 AI 原生输出协议，面向大语言模型（LLM）生成、并由软件系统消费的可靠、确定性、流式友好的结构化数据。

---

## 2. 问题陈述（信息性）

现代 AI 应用越来越依赖 LLM 生成结构化数据。最初为确定性程序设计的格式（尤其是 JSON 与 XML）在长文本与流式生成中会带来挑战：

| 挑战 | 影响 |
| --- | --- |
| 结构一致性要求高 | 长输出更脆弱 |
| 深层嵌套状态难维护 | 失败风险上升 |
| 远距离语法依赖强 | 流式恢复困难 |
| 对部分输出容忍度低 | 增量体验差 |
| 流式生成稳定性不足 | 链路不可靠 |

**理由（信息性）：** XAIOP 围绕 AI 天然的结构化信息生成方式设计协议，而不是强迫 AI 迁就传统序列化格式。

**完整定位（信息性）：** 把「记忆问题」（全局括号 / 嵌套记账）转移成「逻辑问题」（游标下一步往哪走）。证据、按模型画像的有条件收益、协议外瓶颈与当前立场见 **[positioning.zh-CN.md](positioning.zh-CN.md)**。

---

## 3. 架构位置

```text
LLM
 │
 ▼
XAIOP 协议
 │
 ▼
应用 / 下游系统
```

XAIOP 位于模型输出与应用消费之间。它不被定义为通用的程序间数据交换格式。

---

## 4. 目标（规范性意图）

协议设计**必须**追求下列目标：

| 目标 ID | 目标 | 说明 |
| --- | --- | --- |
| G1 | AI 原生 | 适配 LLM 生成行为 |
| G2 | 确定性解析 | 不猜测；不以静默修复作为解析语义 |
| G3 | 流式优先 | 支持增量生成与消费 |
| G4 | 人类可读 | 可作为文本检查与调试 |
| G5 | 跨模型 | 不依赖特定模型的二进制编码即可跨模型家族使用 |
| G6 | 长上下文友好 | 在扩展输出下保持稳定 |

---

## 5. 非目标（规范性）

以下内容明确**不在** XAIOP 作为协议的范围之内：

| 非目标 ID | 陈述 |
| --- | --- |
| NG1 | XAIOP **禁止**被定位为确定性程序之间主要数据交换格式（如 JSON 等）的替代品。 |
| NG2 | 协议**禁止**要求 AI 生成器将哈希、校验和、CRC、长度计算或密码学运算作为符合规范的生成义务的一部分。 |
| NG3 | 符合规范的解析器在输入按协议并非良构时，**禁止**被要求修复、推断或猜测 AI 意图。 |
| NG4 | 正文编码见 `PROT-CONTENT` / `PROT-SYNTAX`。结构规则见 `PROT-BOUND` / `PROT-HIER` / `PROT-SYNTAX`。 |
| NG5 | 本规范树**禁止**将 SDK API 定义为协议要求。 |

## 7. 角色

| 角色 | 职责 |
| --- | --- |
| Generator（生成器） | 产生 XAIOP 文本（通常为受提示或约束的 LLM） |
| Parser（解析器） | 按协议确定性解释 XAIOP 文本 |
| Consumer（消费者） | 使用已解析单元或流的应用逻辑 |
| Downstream system（下游系统） | 存储、转换或展示已消费数据 |

生成器与解析器的精确义务见 `REQ-FUNC` 与 `REQ-STREAM`。
