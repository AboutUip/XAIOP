## 1. 目的

**XAIOP** 是一套**流式、按行、游标构造**的线协议，用于组织结构化数据：写者发出进入 / 回退 / 定位 / 重置 / 删除等指令；解析器**确定性物化**为结构化值（常见为 JSON，含中途相位）。

**一句话：** 写者走游标；程序持有树。

它**不是**服务间 JSON 总线，而是从*增量构造*走到*可消费结构化快照*的桥。

历史全称 “eXtensible AI Output Protocol” **仅作遗留命名**；不定义范围、主用例或符合性。规范性身份是已封存协议包所描述的线格式（见 `META-VER`）。LLM、工具 `encode`、会话推送均为**可选写者场景**（实践层），不是线定义。

封存规则：[../meta/status-and-versioning.zh-CN.md](../meta/status-and-versioning.zh-CN.md) · [../meta/releases.zh-CN.md](../meta/releases.zh-CN.md)。分层：[../SEPARATION.zh-CN.md](../SEPARATION.zh-CN.md)。

## 2. 分层

| 层 | 负责 | 谁 |
| --- | --- |
| **线（协议）** | 游标算子、later-wins、相位重置、诚实解析（默认不静默修复） | 任何符合规范的写者 / 解析器 |
| **实践** | *使用*该线的建议方式（传输、会话、可选模型发射） | 应用 |
| **SDK** | 实现**所引用已封存**协议包的语言 API | 实现方 |

```text
写者（任意符合规范的 Generator）
        │
        ▼
   XAIOP 线（游标 IR）
        │
        ▼
   解析器 / SDK（物化 · 相位）
        │
        ▼
   结构化 Snapshot / Diff → 消费者
```

## 3. 问题陈述（信息性）

为确定性程序设计的格式（尤其是 JSON 与 XML）常要求一次性吐出全局正确的完整结构。这对长文本与增量写者不利：

| 挑战 | 影响 |
| --- | --- |
| 结构一致性要求高 | 长输出更脆弱 |
| 深层嵌套状态难维护 | 失败风险上升 |
| 远距离语法依赖强 | 流式恢复困难 |
| 对部分输出容忍度低 | 增量体验差 |
| 流式生成稳定性不足 | 链路不可靠 |

**理由（信息性）：** XAIOP 围绕**局部游标步骤**与程序侧物化设计，而不是强迫写者模仿括号配对式序列化——把「记忆负担」转为「下一步逻辑」。该设计目标与写者是程序、人或模型无关。

## 5. 目标（规范性意图）

协议设计**必须**追求下列目标：

| 目标 ID | 目标 | 说明 |
| --- | --- | --- |
| G1 | 生成器友好 | 适配增量 / 局部游标书写；避免远距离括号承诺 |
| G2 | 确定性解析 | 不猜测；不以静默修复作为解析语义 |
| G3 | 流式优先 | 支持增量生成与消费；相位友好的物化 |
| G4 | 人类可读 | 可作为文本检查与调试 |
| G5 | 跨写者 | 不依赖特定写者的二进制编码即可跨写者族使用 |
| G6 | 长上下文友好 | 在扩展输出下保持稳定 |

---

## 6. 非目标（规范性）

以下内容明确**不在** XAIOP 作为协议的范围之内：

| 非目标 ID | 陈述 |
| --- | --- |
| NG1 | XAIOP **禁止**被定位为确定性程序之间主要数据交换格式（如 JSON 等）的替代品。 |
| NG2 | 协议**禁止**要求生成器将哈希、校验和、CRC、长度计算或密码学运算作为符合规范的生成义务的一部分。 |
| NG3 | 符合规范的解析器在输入按协议并非良构时，**禁止**被要求修复、推断或猜测生成器意图。 |
| NG4 | 正文编码见 `PROT-CONTENT` / `PROT-SYNTAX`。结构规则见 `PROT-BOUND` / `PROT-HIER` / `PROT-SYNTAX`。 |
| NG5 | 本规范树**禁止**将 SDK API 定义为协议要求。 |

**关于 NG1 的信息性说明：** 产品栈**可以**由程序推送相位（encode、WS 会话）给物化消费端。那是线上的渐进构造——不主张用 XAIOP 替代服务间 JSON 总线。

---

## 7. 范围内 / 不主张

| 范围内（线 + 已封存包） | 不主张 |
| --- | --- |
| 渐进结构化流（游标 IR → 物化 → Snapshot/Diff） | 用 XAIOP 替代服务间 JSON |
| 针对所引用包版本的确定性解析 | 「永远更省 token / 永远快于 JSON」 |
| 不可变的已封存包版本（`META-VER`） | 不带版本号的「最新 Frozen」 |
| 工具与会话共用同一条线 | 把 XAIOP 定义成仅 AI 提示词格式 |

## 9. 角色

| 角色 | 作用 |
| --- | --- |
| Generator（生成器） | 产生 XAIOP 文本（任意符合规范的来源：程序、encode 工具、会话推送；可选 LLM 发射） |
| Parser（解析器） | 按协议确定性解释 XAIOP 文本 |
| Consumer（消费者） | 使用已解析单元或流的应用逻辑 |
| Downstream system（下游） | 存储、变换或展示已消费数据 |

生成器与解析器的精确义务见 `REQ-FUNC` 与 `REQ-STREAM`。
