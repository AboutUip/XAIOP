## 1. 范围

本文档规定生成器与解析器的**与具体格式无关**的功能需求。  
具体句法义务将出现在预留的协议文档中，且**必须**细化而非违背这些需求。

每条需求列出对原则（`P*`）和/或目标/非目标（`G*` / `NG*`）的 **Trace（溯源）**。

---

## 2. 生成器需求

### FR-G-001 文本输出

一旦线格式定义，符合规范的生成器**必须**将 XAIOP 发行为可供人类检查、并可作为字符流传输的文本。

- **溯源：** G4, P1

### FR-G-002 无非语义计算

协议**禁止**要求符合规范的生成器在产生符合规范输出时计算哈希、校验和、CRC、密码学数值或长度字段。

- **溯源：** P2, NG2

### FR-G-003 语义内容责任

符合规范的生成器**必须**仅被视为负责语义内容以及未来语法文档所要求的成帧字符——而非程序侧完整性摘要。

- **溯源：** P2, P3

### FR-G-004 局部产出

协议设计与生成器指导**必须**优先可在无需超出应用语义所需的远距离句法承诺的情况下产出的生成单元。

- **溯源：** P4, P3

### FR-G-005 跨模型中立

协议**禁止**将仅存在于单一专有模型家族的生成器侧特性（例如特定模型的二进制 token 协议）作为符合规范的条件。

- **溯源：** G5, P1

## 3. 解析器需求

### FR-P-001 确定性解释

在相同协议版本与相同良构输入下，符合规范的解析器**必须**产生等价的抽象结果（一旦规定数据模型映射，则对已定义映射具有相同信息内容）。

- **溯源：** P7, G2

### FR-P-002 无静默修复

符合规范的解析器**禁止**将畸形输入改写为猜测的良构形式，并将其作为符合规范的解析行为的一部分。

- **溯源：** P7, NG3

### FR-P-003 显式失败

当输入按适用协议规则为畸形时，符合规范的解析器**必须**发出解析错误（或等价的确定性失败结果），而不是返回被静默“修好”的结构。

- **溯源：** P7, G2

### FR-P-004 不推断意图

除良构输入在协议下字面编码的内容外，符合规范的解析器**禁止**被要求推断缺失语义字段或生成器意图。

- **溯源：** P7, NG3, P3

### FR-P-005 程序侧计算

完整性检查、长度校验、哈希及类似确定性运算——若应用使用——**必须**由程序执行，而非由协议向生成器索取。

- **溯源：** P2

## 4. 协议设计需求（面向编辑）

下列条款约束后续 `protocol/*` 草案：

### FR-D-001 原则相容

未来规范性协议文本**禁止**与 `OV-PRIN` 冲突。

- **溯源：** `OV-PRIN` §1

### FR-D-002 溯源标注

协议草案中新增的 `MUST` / `MUST NOT` 规则**应该**引用原则或目标 ID。

- **溯源：** `META-CONV` §7

### FR-D-003 不取代 JSON

协议理由与定位**必须**与 NG1 保持一致：XAIOP 不是通用的程序间 JSON 替代品。

- **溯源：** NG1

### FR-D-004 人类可读

所选线格式在常规工具（编辑器、日志）下**必须**保持人类可读文本。

- **溯源：** G4

---

## 5. 延后绑定

在可针对线格式完整测试 Core 一致性之前，**必须**先规定下列内容：

| 延后项 | 计划文档 |
| --- | --- |
| 词法 / 句法语法 | `PROT-SYNTAX` |
| 抽象数据模型映射 | `PROT-MODEL` |
| 错误码 / 类别目录 | `PROT-ERROR` |
| 扩展规则 | `PROT-EXT` |

在这些文档离开 `Reserved` 状态前，**禁止**主张完整线格式符合性（见 `CONF`）。
