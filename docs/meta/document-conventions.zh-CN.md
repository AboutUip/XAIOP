## 1. 范围

本文档规定 XAIOP 规范文档的结构、标注、交叉引用与解释方式。  
除非某文档明确记载例外，`docs/` 下全部文档**必须**遵循本约定。

---

## 2. 语言策略

1. 每个逻辑文档对应一份**英文**文件（默认）与一份 `*.zh-CN.md` **中文**镜像。
2. 英文文本为**权威文本**（规范性真源）。
3. 中文镜像**必须**保持相同的章节编号与文档 ID。
4. 若中英文不一致，实现与评审**必须**以英文为准。
5. 英文中不存在的译注**必须**标明为信息性，且**禁止**引入新的规范性要求。

---

## 3. 文档页眉

每份规范文档**必须**以以下内容开头：

1. 一级标题  
2. 语言切换链接（`English` · `简体中文`）  
3. 至少包含下列字段的元数据表：

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| 文档 ID | 是 | 稳定短 ID（如 `REQ-FUNC`） |
| 状态 | 是 | 见[状态与版本](status-and-versioning.zh-CN.md) |
| 版本 | 是 | 规范包版本字符串 |
| 最近更新 | 是 | ISO 日期 `YYYY-MM-DD` |
| 规范性 | 是 | `Normative` / `Informative`，或按节声明混合 |
| 依赖 | 是 | 文档 ID 或 `—` |
| 影响 | 是 | 文档 ID 或 `—` |

---

## 4. 规范性与信息性

### 4.1 规范性

规范性文本定义影响一致性判定的要求。  
第 5 节关键词仅在规范性语境下适用。

### 4.2 信息性

信息性文本提供理由、示例或指导。  
不得仅凭信息性文本主张符合规范。

### 4.3 理由块

作者**应该**使用明确标题或标注为 **Rationale (informative) / 理由（信息性）** 的区块，将理由与要求分开。

---

## 5. 需求关键词

本规范集中的关键词 **MUST**、**MUST NOT**、**REQUIRED**、**SHALL**、**SHALL NOT**、**SHOULD**、**SHOULD NOT**、**RECOMMENDED**、**MAY**、**OPTIONAL**，仅在全大写出现时，按 [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) 解释，并按 [RFC 8174](https://datatracker.ietf.org/doc/html/rfc8174) 澄清。

### 5.1 中文关键词映射（信息性）

| 英文 | 中文镜像用语 |
| --- | --- |
| MUST / SHALL / REQUIRED | 必须 |
| MUST NOT / SHALL NOT | 禁止 |
| SHOULD / RECOMMENDED | 应该 |
| SHOULD NOT | 不应 |
| MAY / OPTIONAL | 可以 |

中文关键词为翻译对应。规范性效力以权威英文文本中的英文关键词为准。

---

## 6. 交叉引用

1. 交叉引用**必须**使用相对 Markdown 链接。
2. 在某一节首次提及其他规范时**应该**附带文档 ID（如 `REQ-FUNC`）。
3. 对预留协议文档的前向引用**必须**声明目标尚不具规范性。

---

## 7. 需求溯源

需求文档中的每一条规范性 `MUST` / `MUST NOT` **应该**可追溯至：

- `OV-PRIN` 中的设计原则，或  
- `OV-INTRO` 中明确的目标或非目标。

**不应**引入无法溯源的孤立要求。

---

## 8. 文档角色

| 角色 | 说明 |
| --- | --- |
| Meta | 规范自身的约定与流程 |
| Overview | 问题界定、范围、原则 |
| Terminology | 已定义术语 |
| Requirements | 与具体格式无关的义务（阶段 1） |
| Conformance | 如何主张符合规范 |
| Protocol | 线格式、数据模型、流式语义（后续） |

---

## 9. 规范文档禁止内容

本目录规范文档**禁止**：

1. 将 SDK API 或语言绑定定义为协议要求  
2. 要求 AI 生成器作为协议义务计算哈希、校验和、CRC、字节长度或密码学数值  
3. 将静默修复、推断或猜测畸形输入规定为符合规范的解析行为  

---

## 10. 变更控制

编辑性与规范性变更遵循[状态与版本](status-and-versioning.zh-CN.md)。
