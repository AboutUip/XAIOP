## 1. 范围

本文规定：

1. 文档 **状态** 标签。  
2. **协议包** 版本与封存规则。  
3. 协议包与 **SDK 包** 版本、**GitHub Release** 的关系。  
4. 某版本封存后 **禁止** 改写的内容。

英文文本为权威；中文镜像 **必须** 与规范性含义一致。

---

## 2. 核心规则（规范性）

**已封存的协议包版本号，其规范性文本对该版本号不可变。**

1. **Frozen（已封存）** 表示：包版本 `X.Y.Z` 的规范性线文本已**封存**。它**不等于**「默认分支尖端上碰巧写着 Frozen 的东西」。  
2. 针对**新**包版本的破坏性或改含义工作 **必须** 在状态 **`Draft`（修订中）** 下进行（或使用显式未发布 SemVer，如 `0.6.0-draft`），直至该新版本封存为 **`Frozen`**。  
3. 封存新版本 **不得** 改写任何先前已封存包版本的规范性文本。旧版本保持 **Frozen** 且可引用。  
4. 已发布的 **SDK** 包版本（npm、Maven 等）**不得** 原地篡改。修复与行为变更 **必须** 以**新的** SDK 包版本发布。这与 [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases) 的不可变发行物模型一致：每个 Release 是固定产物；历史只追加。

---

## 3. 文档状态

每份规范文档 **必须** 声明恰好一种状态：

| 状态 | 含义 |
| --- | --- |
| `Reserved` | 占位；内容**不**具规范性 |
| `Draft` | **尚未封存**的包版本工作稿；**可以**不兼容变更 |
| `Frozen` | 针对**已编号**协议包版本的已封存规范性文本 |
| `Deprecated` | 对新工作不再推荐；先前封存文本仍可引用 |
| `Withdrawn` | 不再属于规范集 |

### 3.1 封存 vs 仓库尖端

| 概念 | 含义 |
| --- | --- |
| **已封存包 `X.Y.Z`** | 对该版本的不可变规范性主张 |
| **默认分支尖端** | **可以**含未来包版本的 Draft、编辑性镜像、SDK 代码与实践文档 |
| **符合性主张** | 实现 **必须** 写明所针对的已封存协议包版本号（如 `0.5.0`），**禁止**只写「最新 Frozen」而不指名版本 |

### 3.2 本仓库中针对包 0.7.0 的工作树

声明 **Version `0.7.0`** 且 **Status `Draft`** 的协议线文档，构成本仓库快照中的 **0.7.0** 工作包。已封存 **0.6.0** 仍可引用且不可变。

若编辑者开启 **0.6.0**（或更新包）为 Draft，这些 Draft 文档头 **必须** 使用新版本号。**禁止**用已封存的 **0.5.0** 头去承载 Draft 正文。

## 4. 协议包 SemVer

1. 协议包版本出现在文档头（如 `0.5.0`）。  
2. **`Frozen`** 包版本 **必须** 使用不含 `-draft` 的纯 SemVer。  
3. 处于不兼容修订中的包版本 **必须** 标为 **`Draft`**（封存前 Version **可以** 使用 `X.Y.Z-draft`）。  
4. 变更类别：

| 变更类别 | 版本动作 | 编辑中状态 |
| --- | --- | --- |
| 仅编辑性（不改规范性含义） | 若该包的 Git 标签已存在，**禁止**改写该标签字节。优先勘误说明，或封存**新**补丁号（如 `0.5.1`）且仅含编辑性修正 | 勘误或新补丁 **`Draft`→`Frozen`** |
| 加法性线变更或任何改变符合性结果的变更 | **必须**分配**新**包版本号，经 **`Draft`** 后封存为 **`Frozen`**。先前已封存号保持不可变 | 新号先 **`Draft`**，再 **`Frozen`** |
| 破坏性线变更（使旧符合文档或解析器失效） | 与加法性相同：新号在 **`Draft`** 下修订直至封存。**0.x** 下升 **次版本**（如 `0.5.0` → `0.6.0`）。宣布 **1.0.0** 后，破坏性升 **主版本** | 新号 **`Draft`** 直至封存；先前已封存版本保持 **`Frozen`** |

5. 在 **0.x** 阶段，本项目以 **次版本** 作为加法性与破坏性协议包的主通道，除非日后宣布 **1.0.0** Stable 系列。调用方仍 **必须** 钉死精确 `X.Y.Z`。

## 5. SDK 包（规范性关系）

1. SDK 包版本（如 npm `@bylan280/xaiop@0.15.1`）**必须**声明其实现的**已封存**协议包版本（如 `PROTOCOL_VERSION = "0.6.0"`）。
2. 发布新的 SDK 版本 **不得** 改写先前已发布 SDK 版本号下的产物或该版本号的变更说明。  
3. 协议包历史与 SDK 包历史**分离**。协议 [revisions.zh-CN.md](revisions.zh-CN.md) **可以** *提及* 哪次 SDK 发行首次实现某线版本；**禁止**把它当作 SDK 的唯一可变变更日志。  
4. 针对协议 `0.4.0` 的旧 SDK 发行，在协议 `0.5.0` 封存后仍是 `0.4.0` 的有效产物。

## 6. GitHub Releases（项目策略）

编辑者 **应该** 发布不可变的 GitHub Release，标签标识已封存产物，例如：

| 标签模式 | 指向 |
| --- | --- |
| `protocol-v0.5.0` | 已封存协议包 `0.5.0`（文档 + 样例） |
| `sdk-nodejs-v0.15.0` | Node.js SDK 包 `0.15.0` |
| `sdk-nodejs-v0.14.3` | Node.js SDK 包 `0.14.3` |
| `sdk-nodejs-v0.14.2` | Node.js SDK 包 `0.14.2` |
| `sdk-nodejs-v0.14.1` | Node.js SDK 包 `0.14.1` |
| `sdk-nodejs-v0.14.0` | Node.js SDK 包 `0.14.0` |
| `sdk-nodejs-v0.13.0` | Node.js SDK 包 `0.13.0` |
| `sdk-nodejs-v0.12.0` | Node.js SDK 包 `0.12.0` |
| `sdk-nodejs-v0.11.0` | Node.js SDK 包 `0.11.0` |

1. 标签发布后，**禁止**将该标签强制挪到不同的规范性字节。  
2. 封存后的修正 **必须** 使用**新**版本号与**新**标签。  
3. 索引见 [releases.zh-CN.md](releases.zh-CN.md)。

## 7. 已封存（`Frozen`）包的变更策略

包版本 `X.Y.Z` 一旦 **Frozen**：

1. 在已存在 GitHub `protocol-vX.Y.Z`（或等价）发行后，**禁止**在同一 `X.Y.Z` 下原地改变规范性含义。  
2. 工作树中的非规范性笔误 **可以** 修正，前提是不影响符合性；若封存标签已存在，则以 **`X.Y.(Z+1)`**（或下一允许号）重新发布，并在 revisions 中明示。  
3. 规范性含义变更时，中文镜像 **必须** 与英文同批发布（且始终作为**新**包版本）。  
4. 实践与 SDK 文档 **禁止** 重定义已封存线规则；冲突时以**所引用版本**的协议包文本为准。

## 8. Reserved 文档

`Reserved` 文档或索引条目：

1. **不得** 被引为建立符合性要求。  
2. **可以** 列出计划中的文档 ID 与标题。  
3. **必须** 声明语法与语义尚未封存。

计划中的 ID（未在 0.5.0 封存）：`PROT-DATA-MODEL`（抽象数据模型——**不是**「大语言模型」）、`PROT-ERROR`、`PROT-EXT`（封存前名称可改）。
